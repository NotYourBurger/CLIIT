# Issue Content Editor

A CLI markdown content editor for the markdown body content where user will be able to write detailed issue brief , headings, bullets,codeblocks and markdown content without worrying about CLI errors, Just free typing

## Closed: not building this

Closed 2026-09-05 after testing the premise instead of assuming it. ISS-012 was
written end to end inside the `description` argument - headings, nested bullets,
an ordered list, a task list and a table all arrived unchanged. Free typing into
the argument is already usable.

The one construct that failed was a fenced code block, and that turned out not to
be this tool. Two PowerShell 5.1 behaviours, hit at once:

- Backtick is PowerShell's escape character. A triple backtick inside double
  quotes collapses to a single one, and a fence at end of line escapes the
  newline into a line continuation - the shell sits waiting for more input,
  which reads as "my description ended".
- PowerShell 5.1 does not quote arguments correctly when calling a native exe.
  `{"a": "b"}` reaches the program as `{a: b}`. The quotation marks were already
  gone before `issue.exe` ran, so nothing in `create_issue` could have kept them.
  Fixed in PowerShell 7.3+; `pwsh` is not installed on this machine.

Git Bash passes fences, quotes and newlines through untouched. That is the
workaround, and it costs no code.

Building a nano-style editor to route around a shell escaping rule is the wrong
size of fix - the editor would be the largest thing in the repo, aimed at a
problem that a different shell already solves.

## If this comes back

The small version is reading the body from stdin rather than an argument:

    issue create "Title" - < brief.md

That sidesteps argument parsing entirely, so no shell can touch quotes,
backticks or newlines. It is a few lines, not a feature, and it kills the whole
class rather than teaching an escaping ritual. File it as its own issue - it is
not this one, and it is not an editor.
