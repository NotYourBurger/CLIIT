# issue log - show an issue's history from git

Every status change and body edit is already recorded, with a date and a commit
message, because issues are files in the repo. Nothing surfaces it.

```
issue log ISS-003
```

runs `git log --follow -- .issues/ISS-003.md` and prints the result.

## Why this is worth more than it costs

No storage changes, no schema changes, no new frontmatter field. It is a
subprocess call and a few lines of formatting. It exists *because* of the
plain-file design - a tracker with a database would have had to build this.

It also makes `updated_at` look thin: that field holds one timestamp with no
idea what changed or why. Git holds all of it.

## Scope

- `issue log <id>` for one issue
- Not found, or not a git repo, or the file has never been committed: say which,
  exit 1, do not print an empty log as if it succeeded
- Uncommitted changes to the issue are invisible to git log - worth a line of
  output saying so rather than looking like nothing happened

## Design notes

`--follow` so a rename does not truncate the history.

Pass `--` before the path so an id that looks like a git revision cannot be
misread as one.

Do not try to pretty-print or parse the git output into columns. Passing
`--format` and letting git write to the terminal is the lazy version and
probably the right one. Resist rebuilding a log viewer.

## Open question

Should this be `issue log` or `issue view --history`? `log` matches what people
already type. `view --history` keeps the id-taking commands to a smaller set.
