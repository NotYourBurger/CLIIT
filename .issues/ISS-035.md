# Duplicate ids: name the ceiling on next_id, and catch the residue

`convert_id.next_id` allocates one past the highest id in one directory
listing. Two agents in two git worktrees - the audience this tool keeps
naming - both allocate ISS-032.

Narrower than it first looks: both then create ISS-032.md, and git raises an
add/add conflict on merge. The collision is loud, not silent.

What is silent is the residue. Resolve that conflict by keeping both files
under different names and `check` builds `by_id` keyed by id, where the second
one overwrites the first without a word. One issue disappears from `list`,
from `next`, and from every blocker lookup, and nothing says so.

## The fix

- A duplicate-id finding in `check`, where `by_id` is built. A few lines.
- A `ponytail:` comment on `next_id` naming the worktree ceiling and the
  upgrade path, the way every other deliberate shortcut here is marked.

## And the orphaned check

`tests/all.py` globs `test_*.py`, so `convert_id.py`'s inline self-check - the
one guarding the thing that must never collide or burn a number - runs only
when a human types the separate command written in CLAUDE.md. That is a habit,
not a suite. Give it a `tests/test_convert_id.py` that calls it, or teach
`all.py` to run it.

## Acceptance

- two files carrying the same `id:` are a finding, naming both files
- the finding does not fire on two different prefixes numbering independently
- id allocation is checked by `uv run python tests/all.py`
