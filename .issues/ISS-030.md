# issue check - the doctor for the format that is the API

The file format is the API, and its worst failure does not raise. A parser bug
returns a plausible dict that gets written back over the user's prose, quietly,
and the first person to notice is reading a mangled issue weeks later.
`tests/test_storage.py` guards the shape with one deliberately nasty body. It
does not guard the twenty-six real files on disk, and those are the ones that
matter.

One new verb and one new module, `check.py`, beside `validate.py` - the layer
that already owns "pass, or exit 1 saying why".

1. **Round trip.** For every `.issues/*.md`: parse, write to a buffer, compare
   bytes. The only failure class here that corrupts silently.
2. **Dangling blockers.** `brief` already prints these as WARNINGS; `check`
   reuses that and makes them exit non-zero.
3. **Unrecognised values.** A hand-edited `status:` or `priority:` outside the
   tuples. `actionable()` drops those silently today, so an issue can vanish
   from `next` with nothing said about it.
4. **Orphan plans.** `.issues/work/ISS-NNN.md` with no issue beside it.

Exit 0 clean; exit 1 with the findings on stderr, and on stdout under `--json`.

Not checked: a hand-edited `labels: auth, sessions`. After the split it is
indistinguishable from two labels - undetectable by construction, and a check
that pretends otherwise is worse than none.

## Acceptance

- a clean tempdir is exit 0 and silent
- a hand-written `status: wip`, a dangling blocker and an orphan plan are each caught
- one check runs against the real `.issues/` and asserts exit 0 - the way
  `test_storage.py` and `test_encoding.py` already read this repo
- `tests/all.py` invokes it, so round-trip corruption fails the suite
