# Globally unique issue ids, with no coordination

`next_id` allocates one past the highest id in one directory listing. A
listing cannot see a branch that is not checked out, a sibling worktree, or
another clone, so two agents both mint `ISS-059`. `reserve_id`'s `O_EXCL`
(ISS-039) closes the race inside one filesystem and nothing closes it across
two.

Five documents currently answer this by telling the user to coordinate -
README Scope, SECURITY.md, CONTRIBUTING.md, the PR template, ISS-050. That is
the wrong answer for the audience this tool keeps naming: agent-heavy Git
workflows are exactly where nobody is coordinating.

Make the id globally unique instead. This is a breaking change to the id shape
and is deliberate.

```
ISS-0m4k3f9a
|   |     |
|   |     +-- 4 chars base36 random             -> offline-unique
|   +-------- 6 chars base36 seconds-since-2020 -> still sorts by creation
+------------ prefix, unchanged, still $ISSUE_PREFIX
```

- `storage.ID` widens to `[A-Za-z]+-[0-9A-Za-z]+$`. Still alphanumeric, so it
  still contains no `/`, `\` or `.` and `require_id` remains the
  path-traversal guard ISS-040 made it.
- Generated lowercase only. Windows and macOS filenames are case-insensitive,
  so `ISS-00a` and `ISS-00A` would be one file. Generating one case makes that
  unreachable; the regex still accepts uppercase for hand-written and
  grandfathered ids.
- `next_id` is deleted. Nothing scans for a highest number any more - the scan
  was the bug. `reserve_id` keeps its `O_EXCL` retry loop, now guarding a
  genuine rare random collision rather than a race.
- Old ids are grandfathered, not migrated. ISS-001..ISS-058 keep their names,
  files, history and commit prefixes. An upgrade never rewrites a tracker.

The rejected alternative: allocate from `git log --all` so an id used on any
ref is taken. It fixes branches, worktrees and clones that have fetched, but
not two clones that have never synced - which is the case actually being
complained about - and it needs a second mechanism to get the path filtering
and the degradation right. Random ids need one.

Docs that become false and change here: README's Scope IMPORTANT block
(README.md:236-239) states the opposite claim; SECURITY.md:59-60 loses the
"not unique across clones" non-goal; CONTRIBUTING.md:21-27 and
`.github/pull_request_template.md:15-18` both correct the false "git merges
them with nothing to show you" and relax the rule - a pull request may now
create an issue file, which retires ISS-052's conclusion.

## Acceptance

- two `.issues/` trees with no shared history generate disjoint ids, offline
- generated ids are lowercase, match the widened `ID`, and sort by creation
- ISS-001-style ids still parse, list, view, set, close and log
- `next_id` is gone; `reserve_id` keeps the O_EXCL retry
- `tests/test_id_scheme.py`, including the two-independent-clone case
- `tests/test_stability_contract.py`'s ISS-001.md / BUG-001.md assertions
  (lines 280, 288) are updated - those two edits are the migration
- `tests/test_concurrency.py`'s `next_id` assertions (68-99) removed,
  `reserve_id` ones kept
- README, SECURITY.md, CONTRIBUTING.md and the PR template no longer claim ids
  can collide
