# There is no released version to install

Install in README is `uv sync`, which is a sentence written for somebody who
has already cloned. There is no tag, nothing on PyPI, and no path from a
commit to a thing a stranger can install. Ninety-five commits of a tool
finished enough to document its own stability, and no way to get it.

The publish is a one-way door and is worth walking through deliberately. A
PyPI name cannot be reused after deletion, and `issue` is a generic enough
entry-point name to collide with something already on somebody's PATH. Both
are decisions to make before the upload rather than after it.

The release has to be cut by CI on a tag and not from a laptop. The `wheel`
job already proves a built wheel installs into a clean venv and runs with no
source tree in sight; publishing is that job with an upload on the end and the
tag checked against the version. The version lives in `pyproject.toml` alone
and `issue --version` reads it back from the installed distribution, so a tag
is the second place the number can appear - and the second copy of one number
is the bug that job exists to refuse.

## Scope

- make the repository public. `git ls-remote` succeeds with the local
  credentials and an anonymous fetch of the same URL is a 404, so today there
  is no install path for a stranger by any spelling, and the three URLs in
  `pyproject.toml` resolve to nothing. Everything else here is downstream of
  this one line.
- turn on private vulnerability reporting at the same moment. It is a public
  repository feature - the API is a 404 today - and SECURITY.md names an
  email address only because of that (ISS-057)
- reserve the PyPI name `cliit`, and confirm `issue` is an entry-point name we want to
  hold
- a release workflow on tag push: the full matrix passes, then build, then
  publish by trusted publishing rather than a stored token
- the job refuses a tag whose version disagrees with `pyproject.toml`
- CHANGELOG.md, starting at this release
- README's Install section rewritten for somebody who has not cloned

## Acceptance

- `pip install cliit` into a clean venv gives working `issue` and `cliit` commands
- a mismatched tag fails the job rather than publishing
- CHANGELOG names what the first release contains
