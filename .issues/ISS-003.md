# Swithcing status Open/Closed

Status of an issue can be `open` or `closed`.

## Commands

| Current status | Command             | Result   |
| -------------- | ------------------- | -------- |
| `open`         | `issue close <id>`  | `closed` |
| `closed`       | `issue open <id>`   | `open`   |

## Implementation sketch

The status lives in one frontmatter line, so a change means *rewriting the
file* with that line swapped. The body must survive untouched.

```python
issue = parse_issue(path)
issue["status"] = "closed"
write_issue(path, issue)   # <- this helper does not exist yet
```

> **Careful:** `create_issue` currently builds the file with an f-string.
> Adding a writer here means two places that know the file format.
> Extract one `write_issue` and have both call it.

## Edge cases

- Closing an already-closed issue — say so, don't rewrite
- Unknown id — print the id and suggest `issue list`
- Should closing stamp a `closed_at` field?
