# Release 0.1.1 with a fixed hero, install line and terminal demo

Three launch-polish problems, one release. The README hero and install line are
what the PyPI page shows, so they have to be fixed *before* 0.1.1 is cut - a
second release to fix copy is the thing this issue exists to avoid.

1. **The live PyPI page still shows the old GitHub install command.** The README
   in the repo already says `uv tool install cliit`; the published 0.1.0 page
   does not. Promoting the tool now sends people to two different sets of
   instructions. Fix: cut 0.1.1 so the page carries the current README.

2. **Sharpen the README hero.** Suggested copy:
   > Markdown-native issue tracking for coding agents.
   > Keep issues, work plans, claims, and completion evidence in Git. No server
   > or account required.

3. **Add a 20-30 second terminal demo.** One run: `init --agents` -> `create` ->
   `next --claim` -> `start` -> `close`, then show the Markdown files and the
   git diff. The point of the demo is that the database is the files, so the
   files and the diff are the payoff, not the CLI output.

Acceptance:
- README hero reads as above (or better), install line unchanged.
- Demo recorded, committed, and linked from the README above the fold.
- 0.1.1 on PyPI, its project page showing the new hero and `uv tool install
  cliit`, verified by loading the page.
