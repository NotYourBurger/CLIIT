# A newline in a label rewrites the frontmatter under it

`clean_set` is documented as the one shared validation the file format rests
on, and it enforces exactly two rules: not empty, and no comma. A value may
still contain a newline - and frontmatter is line-oriented, so a newline in a
value is not data, it is a new field.

Through the real validator and the real writer:

    validator accepted: ['bug\nstatus: closed\nassignee: mallory']

    ---
    id: ISS-001
    status: open
    ...
    labels: bug
    status: closed
    assignee: mallory
    ---

    status after:  closed
    assignee after: mallory
    VERDICT: INJECTED

An open issue is now closed, and owned by someone who never claimed it.

The reason this is worse than a malformed file: CLAUDE.md states that
`close_issue()` is the only thing that writes `status: closed`, and
`set_fields` refuses the word by name so the rule holds at the front door. A
label walks straight past it. The invariant the evidence rule depends on -
nothing is closed without evidence - is not actually enforced by the format.

The likely source is not an attacker. It is a paste: an agent or a person
passing a multi-line string to `--label`, or a shell heredoc that keeps its
newline. The tool accepts it silently and the damage is only visible on the
next read.

Comma is validated because it is the delimiter between values. Newline is the
delimiter between fields, and is the more dangerous of the two.

## Scope

Centrally, in `clean_set`, so labels and blocked_by are both covered by one
rule, along with anything a later field routes through it. Reject any control
character and reject a leading `-` or a value that is only whitespace.

The same class of unchecked input, worth settling in one pass:

- `ISSUE_PREFIX` goes into a filename with no validation at all; a prefix
  containing a path separator writes outside `.issues/`.
- an `id` argument is joined onto the issues directory in `read_issue`,
  `log_issue` and `plan_path` without ever being checked against the id shape.

## Acceptance

- a label or blocker containing a newline or carriage return is refused, before
  any write, with a message naming the character
- the same refusal covers a control character and a leading `-`
- an id that is not the documented shape is refused rather than joined onto a
  path; a prefix that is not letters is refused by `create`
- existing valid labels, unicode included, still round trip unchanged
- a test that writes the injection payload and asserts status is untouched
