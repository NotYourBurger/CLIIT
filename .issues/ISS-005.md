# Issue Id Initialization

Currently Issue Id is hard coded, We need to either manually or automatically create isssue id then continue incrementing over the id

## What is left after ISS-012

Allocation itself is done - `next_id()` reads the highest `ISS-NNN` on disk and
adds one - and ISS-012 took "where issues live is hardcoded" with it. What
remains is only the `ISS-` prefix, hardcoded in three places that must agree:
`next_id()`, the `filename.startswith("ISS-")` filter in `list_issues()`, and
the README. A configurable prefix means one constant those three read, and a
decision about where it is configured.
