# Cut 0.2.0 with the id migration

ISS-059 breaks the id shape, which is a documented stability contract, so the
release is its own unit of work - `docs/RELEASING.md` already describes the
tag-driven job and the maintainer-approved `pypi` environment.

- `docs/MIGRATION-0.2.md`: what changed, that no existing issue is renamed,
  that old and new ids coexist permanently, and that any consumer regexing
  `ISS-\d+` out of `--json` or a commit message must widen it.
- README Stability: the id shape stated as a contract with this break named.
  Also fix "currently 0.1.0", which already disagrees with `pyproject.toml`'s
  0.1.1 - the 0.1.1 release did not update the line.
- README Usage gains `renumber`; File format's `id: ISS-001` example shows the
  new shape.
- CLAUDE.md: the id scheme and why, the `renumber` verb, the journal as a
  fourth artifact in `.issues/`, the deletion of `next_id`.
- CHANGELOG.md 0.2.0 with a Breaking section; `pyproject.toml` to 0.2.0.

## Acceptance

- `uv run python tests/all.py` green, `uv run issue check` clean
- migration doc written; README, CLAUDE.md and CHANGELOG agree with the code
- no document still claims ids can collide across clones
- 0.2.0 on PyPI, its project page verified by loading it
