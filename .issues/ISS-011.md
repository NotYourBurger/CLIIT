# Errors belong on stderr, failures belong in the exit code

`--json` turned two long-standing cosmetic problems into real ones. A script
consuming this tool currently cannot tell success from failure.

## 1. Two error paths print to stdout

```
$ issue list --json          # in a directory with no .issues/
Please Run - issue init - to initialize the project first
$ issue list opne --json
Unknown status 'opne' - use: in-progress, open, closed
```

Both are English sentences on stdout where a parser expects JSON.

`view_issue` already routes its not-found message to stderr - these two were
missed because they live in the *shared* helpers rather than at the call site:

- `require_issue_dir` in `storage.py` (needs `import sys`)
- `check_status` in `issues.py`

Fixing them there covers every command at once. Leave `"No issues yet"` and
`"No {status} issues"` on stdout - they are informational, not errors, and they
sit after the `--json` return so they can never contaminate it.

## 2. Every failure exits 0

```
issue list opne         -> 0
issue view ISS-999      -> 0
issue set ISS-999 open  -> 0
```

So `issue list open --json` returning `[]` (no open issues), a sentence
(not a repo), and a bad status word are indistinguishable to a caller.
`issue set X closed && git commit` cannot work.

### The design question

`raise typer.Exit(1)` is the one-liner, but `typer` currently appears only in
`cli.py` - `issues.py` and `storage.py` know nothing about the CLI framework,
which is why the logic is testable. Importing typer into `issues.py` to raise
from there would spend that separation.

The alternative is for the `issues.py` functions to return success/failure and
let `cli.py` translate that into an exit code. More plumbing, keeps the layers.

Decide which before writing it. Partial failure needs a rule too: `issue set
ISS-001 ISS-999 closed` sets one and fails one - is that exit 0 or 1?

## Not in scope

`issue list --json | head` raises `OSError: [Errno 22]` on the broken pipe.
Same area, different bug. File separately if it becomes annoying.
