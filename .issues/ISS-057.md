# No channel for a security report and no stated house rules

A vulnerability in a tool that writes files, holds a lock and shells out to
git has nowhere to be reported except the public tracker, which is the one
place a report like that should not go first. There is also no stated answer
for how conduct is handled, which has never come up because there has only
ever been one person here - and which stops being true on the day this is
worth contributing to.

Both are cheap, and both are gates: they are among the things a stranger
checks before spending an evening on a pull request.

## Scope

- SECURITY.md: what counts as a vulnerability in a local CLI, where to send
  one privately, and what response to expect
- CODE_OF_CONDUCT.md: Contributor Covenant, with a contact address that is
  read
- issue and pull request templates matching whatever ISS-052 decided about
  where things get filed

## Acceptance

- a private reporting channel exists and is named
- the bug template asks for `issue --version` and the OS, which is what a
  report here actually needs
- no template contradicts the filing policy
