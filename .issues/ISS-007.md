# Round trip tests for the issue file format

`parse_issue` and `write_issue` are exact inverses, and nothing checks that they
stay that way. The project has zero tests.

## Why this one first

The parser has already broken twice in this repo's history, both times silently:

- a `# ` heading in the body overwrote the title (last-wins instead of first-wins)
- a `---` horizontal rule in the body was read as the end of the frontmatter,
  swallowing the next paragraph as a field

Both were found by eye, after the fact. A parser bug does not raise - it returns
a wrong dict, and `write_issue` then persists it. **That is the one path in this
codebase that can lose your writing.**

## Scope

One `test_storage.py`, no framework, plain `assert` under `if __name__ == "__main__"` -
same shape as the self-check already in `convert_id.py`.

```python
issue = parse_issue(path)
write_issue(issue)
assert parse_issue(path) == issue      # stable across a rewrite
```

Fixtures should include the nasty body: a `# ` heading, a `---` rule, a table,
a fenced code block, a blockquote. `.issues/ISS-003.md` is already exactly that
file - copy it into a temp dir rather than writing against the real `.issues/`.

## Not in scope

Testing the print functions. They are `print` calls with no branching worth
guarding; the round trip is where the risk is.
