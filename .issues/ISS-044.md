# issue init tells the agent to use a tool it never names

`issue init` is the one moment this tool writes outside `.issues/`, and its
whole job is putting the workflow rule where the agent reads it. That part
works: `write_rule` appends to CLAUDE.md and AGENTS.md, appends rather than
truncates, and is idempotent on the rule's first line
(tests/test_plan.py:96). Two things it does not do, and both only show up in
a repo that is not this one.

**The rule never names the tool.** `RULE` (plan.py:46) is nine lines about
work plans: read the issue, create a plan, tick the checkpoints, close when
complete. It does not contain the word `issue`, does not say `.issues/` is
the tracker, and names not one verb. An agent that lands in a fresh repo and
reads only that section has a procedure and no way to invoke it - "Read the
issue and any existing active work plan" with which command?

It reads fine here only because roughly two hundred hand-written lines above
it explain the tool. This repo has never experienced the case the feature
ships for.

**Nothing happens, silently, when neither file exists.** `write_rule` skips
any project file that is not already there, which is the right default -
inventing a CLAUDE.md in a repo that never had one is a decision about that
repo's conventions the tool has no standing to make, and init.py says so.
But the current behaviour is to make that decision by saying nothing at all.
A new user in an unknown repo runs `issue init`, sees "Feel free to explore
.issues folder", and never learns that the agent half of the tool did not
install.

## Scope

Do not grow `RULE`. It is shared with the seeded plan through `RULE[4:8]`, so
a tool-usage line added there leaks into every work plan's HTML comment.

A second constant in `init.py`, appended by the same idempotent loop: a short
block naming the tracker and the four verbs an agent actually needs -
`issue next`, `issue start ISS-NNN`, `issue check`, `issue close`.

For the no-file case, keep the principle and drop the silence: say on stderr
that neither file exists and that the agent instructions were not written,
with a flag that writes one when the user asks for it.

## Acceptance

- the text `init` appends names the `issue` command and at least `next`,
  `start`, `check` and `close`
- `RULE` is unchanged, and a seeded work plan's reminder is byte-identical to
  what it is today
- running `init` twice still appends once, tool block as well as rule
- a directory with neither CLAUDE.md nor AGENTS.md gets a message on stderr
  saying no agent instructions were written, and the exit code stays 0
- an explicit flag creates one when asked
- tests/test_plan.py covers the fresh-repo case, which it currently does not
