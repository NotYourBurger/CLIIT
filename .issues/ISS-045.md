# AGENTS.md is an untracked stale copy of CLAUDE.md

`write_rule` appends to CLAUDE.md and AGENTS.md both, and init.py gives the
reason: "two agents reading two files is exactly the case one of them exists
for." In this repo the two files have already drifted.

AGENTS.md is untracked - it is the `??` in git status - and its body is a
stale copy of CLAUDE.md that predates ISS-038 through ISS-043. It still
describes `clean_set` as enforcing "not empty, no comma", which ISS-040
changed; it lists the layers without `events.py`; it does not mention
`write_atomic`, `storage.locked` or `require_id`. An agent that reads
AGENTS.md instead of CLAUDE.md is working from instructions this repo
retired.

`write_rule`'s idempotency check cannot notice. It looks for the rule's first
line, which is present in both files, and says nothing about the two hundred
lines above it.

## Scope

A decision, not much code. Either AGENTS.md is a file this repo keeps - in
which case commit it and keep it in step with CLAUDE.md - or it is not, in
which case delete it and let `init` create it for the repos that do use one.

Worth settling in the same pass: whether `issue check` should notice that a
repo's two agent files disagree. That is the same shape of question it
already asks of a work plan and the issue beside it.

## Acceptance

- the repo has one written answer about AGENTS.md
- if kept: tracked in git, and its content matches CLAUDE.md
- if dropped: removed, and CLAUDE.md notes that `init` writes it for repos
  that keep one
