# The suite fails on a clone whose .issues differs from this one

Nineteen of the twenty-one test files isolate into a `TemporaryDirectory`
with `ISSUES_DIR` set, so the suite does not touch a user's tracker. Two do
not, on purpose:

- `tests/test_check.py:453` points `ISSUES_DIR` at the repo's real
  `.issues/` and asserts `check` exits clean. The comment gives a good
  reason - "the day a parser change starts eating prose it fails here rather
  than in an issue nobody reopens for a month."
- `tests/test_storage.py:83` copies the real `.issues/ISS-003.md` as its
  round-trip fixture.

Both are reads, so nothing is corrupted and no one's issues are rewritten.
But both make the suite's result depend on repository state rather than on
the code. A contributor who files an issue while working - which this repo's
own workflow tells them to do - can fail a test that has nothing to do with
their change, and a clone where ISS-003 has been renamed or closed
differently fails outright.

## Scope

Keep the intent and drop the coupling: a small committed corpus under
`tests/fixtures/` that both the parser round trip and the whole-directory
check run against, with ISS-003's body carried in as one of them.

Whether the real `.issues/` should still be checked as well, as a separate
opt-in script rather than part of `all.py`, is worth deciding in the same
pass.

## Acceptance

- `uv run python tests/all.py` passes on a clone with an arbitrary `.issues/`
- the nasty-body round trip still runs against content equivalent to ISS-003
- a parser change that eats prose still fails the suite
