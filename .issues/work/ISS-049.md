# ISS-049 Work Plan

## Goal

The suite fails on a clone whose .issues differs from this one

## Plan

- [x] Commit a corpus under `tests/fixtures/` - real prose, one file per shape
      the whole-directory pass cares about, ISS-003's body carried in
- [x] `tests/helpers.py`: a `FIXTURES` constant beside `REPO`
- [ ] `tests/test_storage.py:83`: copy the fixture, not `.issues/ISS-003.md`
- [ ] `tests/test_check.py:453`: point `ISSUES_DIR` at the fixtures
- [x] `.gitattributes`: pin the fixtures to LF, same reason as `.issues/`
- [x] Decide the real-`.issues/` question and act on it
- [x] `uv run python tests/all.py`, and the same on a scratch clone with a
      different `.issues/`

## Decisions

- The corpus is four files, not a copy of `.issues/`. Three issues covering the
  shapes the whole-directory pass has an opinion about - a pre-`updated_at`
  file (ISS-003 verbatim), a live one carrying every optional field plus an
  unknown key put there by hand, and a closed one whose `evidence` line is
  JSON - and a README saying what it is for. A file gets added when a new
  shape becomes possible, not when an issue is filed.
- No opt-in script for the real `.issues/`. `uv run issue check` already is
  that script; writing a second one that shells out to the first is a file
  with nothing in it. CI got the step instead, because there the repository
  state under test *is* the branch that changed it - which is the difference
  between the coupling this issue is about and a useful check.
- `check --plans` comes out of the suite entirely and does not come back as a
  fixture. It reports how well the work plans are kept, which is a fact about
  the people and not the code; `check_plans` itself is already covered by the
  temp-dir fixtures in item 6 of the same file. It runs in CI for the log.
- The suite asserts the fixture directory is non-empty before checking it. An
  empty `ISSUES_DIR` passes `check` while proving nothing, and that is exactly
  what a moved or renamed fixture directory leaves behind.

## Discoveries

- `tests/fixtures/README.md` is safe to keep next to the corpus: `check` walks
  every `.md`, but a file with no frontmatter round trips unchanged and only a
  file whose *name* is an id is a finding when it will not parse (ISS-042).
- The first corpus was not strong enough. Broke `split_file` in a clone so the
  fence search finds the *last* `---` - the exact "eats prose" regression item 7
  exists for - and `test_storage`'s NASTY_BODY caught it while the fixtures did
  not: not one of the three had a bare `---` rule in its body. ISS-004 carries
  one now, plus a blockquote as the last line and a fence containing `---`, and
  the whole-directory pass fails on that change too. A corpus nobody wrote to
  fail a rule still has to be chosen.
- The `.py` sources here are CRLF in the working tree, so an edit that rewrites
  one as LF shows up as a whole-file diff. The fixtures needed the same
  `.gitattributes` pin `.issues/` has for the opposite reason - `check`
  compares a file against its own rewrite byte for byte.

## Current

All three acceptance lines hit. Documented the convention in CLAUDE.md so the
next test that wants a real corpus does not reach for `.issues/` again.
