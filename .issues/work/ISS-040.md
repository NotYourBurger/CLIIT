# ISS-040 Work Plan

## Goal

A newline in a label rewrites the frontmatter under it

Three unchecked inputs, one class: a value that carries a delimiter the format
reads as structure. Settle all three in one pass so the format has one rule per
delimiter rather than one per field.

## Plan

- [x] test: a label containing a newline is refused before any write
- [x] fix: `clean_set` rejects control characters, a leading `-`
- [x] test: an id that is not the documented shape is refused, not joined onto a path
- [x] fix: one id-shape guard in `storage.py`, called by `read_issue`, `log_issue`, `append_event`
- [x] test: a prefix that is not letters is refused by `create`
- [x] fix: `id_prefix` validates
- [x] full suite green, README/CLAUDE.md in sync

## Decisions

- Seam is the repo's existing one: command functions through `helpers.run()`,
  asserting exit code, stream and the bytes on disk.
- The id guard goes in `storage.py`, not `validate.py`: `read_issue` is the
  lowest layer that joins an id onto a path, and it cannot import upward.
- `id_prefix()` validates rather than `create` doing it, because `id_prefix` is
  the only reader of the variable - one place, and `create` gets it for free.

## Discoveries

- The rule that covers the harm is not "no newline" but "one printable line":
  `split_file` reads with `splitlines()`, which also breaks on a vertical tab,
  a NEL and U+2028. `str.isprintable()` is that rule in one call.
- Guarding `plan_path` broke `issue check --plans`: it walks `work/` and hands
  `read_plan` the names it found, and a stray `notes.md` there turned a report
  into an exit 1. `read_plan` is documented as never raising, so the guard
  belongs at the door and not in the path builders. Reproduced, then fixed, then
  pinned by an assertion in the new test.
- The three doors are `read_issue` (nearly every verb), `log_issue` (the one
  verb that builds its own path) and `append_event` (the one write that creates
  a file from an id). `start` needs none: it looks the id up in `by_id`.
- `sys.exit("message")` sets the exit *code* to the string. Every validator here
  prints to stderr and exits 1, and `helpers.run` reads `exit.code` - so the new
  prefix check does the same.
