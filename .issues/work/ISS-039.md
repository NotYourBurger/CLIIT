# ISS-039 Work Plan

## Goal

Two writers in one worktree: a claim both agents win, an id two issues share

## Plan

- [x] `storage.locked()` - an OS advisory lock on `.issues/.lock`
- [x] `convert_id.reserve_id()` - allocate by O_EXCL create, not by asking who is highest
- [x] `create_issue` calls `reserve_id`; `try_claim` wraps its read-validate-write in `locked()`
- [x] `tests/test_concurrency.py` forcing both interleavings
- [x] `.gitignore` the lock file; README / CLAUDE.md if the contract changed
- [x] full suite green

## Decisions

- **OS advisory lock (`fcntl.flock` / `msvcrt.locking`), not an O_EXCL lock file
  with a timeout.** Both are ~20 lines. The kernel drops an OS lock when the
  holder dies, so the "a killed process must not wedge the tracker" acceptance
  criterion costs nothing; an O_EXCL lock file has to guess staleness from an
  mtime, and two processes deciding a lock is stale at the same moment is the
  bug it was meant to fix wearing a hat.
- **Id allocation gets O_EXCL, not the lock.** The issue asks for it and it is
  the stronger answer: the loser gets `FileExistsError` and retries, so it is
  correct across worktrees and machines where a lock file under one `.issues/`
  is not.
- **The lock is global (one file), not per-issue.** This is a CLI run from a
  prompt; contention is two agents, not two hundred.
- **Only `try_claim` takes it.** `set_fields` must not, or `try_claim` would
  nest and self-deadlock on Windows, where the lock is per-fd and mandatory.

## Discoveries

- **`test_assignee.py` was testing the mechanism, not the guarantee.** It
  staged the losing interleaving by stubbing `set_fields` to write somebody
  else's name, and asserted `try_claim` believed the file over its own write.
  That check is about the read-back, which is gone; the guarantee it stood for
  is now forced with a real second process in `test_concurrency.py`. Removed
  it and said in the docstring where it went, rather than bending it to pass.
- **A 0-byte `.md` in `.issues/` was invisible to every command, `check`
  included.** Every reader goes through `parse_issue` and skips what it
  rejects, which is right for `list` and silence everywhere else. Reservation
  makes that shape reachable - a create that dies between the O_EXCL and the
  write leaves exactly one - so `check` now names it. Four lines, and it is
  the visible half of the trade the reservation makes.
- **The lock must not be reentrant-by-accident.** On Windows `msvcrt.locking`
  is per-fd, so `try_claim` taking the lock and then calling a `set_fields`
  that also took it would deadlock against itself. One taker, named in
  CLAUDE.md so the next writer does not add a second.
- `open(..., "a")` leaves the file pointer at the end and Windows locks from
  the current position, so `_take` seeks to 0 rather than relying on the lock
  file staying empty forever.
