# ISS-048 Work Plan

## Goal

requires-python >= 3.13 is not backed by anything

## Plan

- [x] read the issue and find out what pyproject actually says today
- [x] measure whether the suite passes on 3.10 (the next rung down)
- [x] set the floor and the matrix to whatever that measurement says
- [x] run the suite on the floor and on the dev interpreter
- [x] close with evidence

## Decisions

- Floor is 3.10, not 3.11. 3.11 was the lowest number ISS-047 happened to
  try, which is the same shape of unmeasured claim this issue was filed
  about. Stopping at 3.10 rather than going lower: 3.9 went end of life in
  October 2025, so 3.10 is the oldest interpreter still getting security
  fixes, and typer reads `X | Y` annotations at runtime, which is 3.10.
- The one thing that failed on 3.10 was `tomllib` in `tests/test_version.py`,
  not a line of the tool. Same call ISS-047 made about its own git fixtures:
  a test red by construction is a broken test, not a finding about the floor.
  `test_version` now skips only the half that reads pyproject and still runs
  `--version` against `importlib.metadata`, so the new matrix row exercises
  the flag rather than returning early.

## Discoveries

- ISS-047 already did most of this issue as a side effect: it widened
  `requires-python` from `>=3.13` to `>=3.11` after running the suite on a
  real 3.11, and added the classifiers and the 3.11/3.12/3.13 CI matrix.
  So the acceptance line "matches the oldest version the suite passes on in
  CI" is already true. What is left is whether 3.11 is the real floor or
  just the lowest number ISS-047 happened to try.
