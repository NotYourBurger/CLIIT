# ISS-038 Work Plan

## Goal

Every write truncates first, so a failed write erases the issue

## Plan

- [x] one atomic write helper in storage.py, beside write_issue
- [x] write_issue uses it
- [x] write_plan uses it
- [x] tests/test_atomic.py: injected failure, original survives, no temp left
- [x] full suite green
- [x] the rule written down in CLAUDE.md beside the UTF-8/LF one

## Decisions

- The helper lives in storage.py because plan.py already imports from it and
  storage is the lower layer; the import direction stays one way.
- Temp file suffix is not `.md`, so every reader (which filters on `.md`)
  ignores it during the window it exists.
- fsync before the replace, not just flush. The replace alone is atomic against
  another reader; the fsync is what makes it atomic against the power going
  out, which is one of the ways the issue says this window was reached.
- One `finally` that unlinks the temp path if it still exists covers both the
  success and the failure path - after a successful replace there is nothing
  there to remove, so there is no second branch to get wrong.
- `append_event` and `init` are left exactly as they are. Both append and never
  rewrite, which is already the property this issue wants.

## Discoveries

- The test injects the failure by rebinding `storage.open`, and the last
  assertion in it points that same injection at a plain truncating write and
  asserts the file *does* end up 0 bytes. Without that, an injection that
  stopped firing would leave every other assertion passing and prove nothing.
- The proxy's `__exit__` has to close the real handle: on Windows an open
  handle cannot be unlinked, so the cleanup path could not remove its own temp
  file otherwise.
