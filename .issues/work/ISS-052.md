## Decisions

- GitHub Issues is the door, `.issues/` is the source of truth. A door needs
  no clone, no id and no fork, which is the whole reason a stranger uses one;
  the tracker stays the backlog rather than a copy of one. No mirror is built
  in either direction - the issue asked for the decision, not a mechanism, and
  a stale mirror is the failure mode that reads as authoritative.
- A pull request may edit an existing `.issues/*.md` but may never create one.
  That is the whole id-allocation answer and it costs nothing to enforce:
  creation is the silent failure (two forks both write a valid `ISS-052` and
  git merges them without a conflict), editing an existing file is an ordinary
  conflict when it is one at all. README's Non-goals already admitted this
  race - "two people creating offline both get ISS-051" - and this is the
  contribution-side rule that follows from it.
- The paragraph lands in README only, not in a CONTRIBUTING.md written here.
  ISS-056 owns that file and its scope already names "the answer ISS-052
  gives"; writing a stub now is the second copy of one paragraph that ISS-045
  says goes stale. ISS-052's acceptance criteria are all README's.

## Discoveries

- `pyproject.toml` already points Issues at GitHub, so the decision was

- The GitHub repository is still private (ISS-055 established this), so the
  filing link 404s for a stranger until ISS-054's first scope line lands. The
  policy is correct now and reachable then; no wording has to change.
