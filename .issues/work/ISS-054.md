# ISS-054 Work Plan

## Goal

There is no released version to install

- [x] make fresh projects discoverable by both Codex and Claude Code

## Decisions

- Keep MIT, which is already declared consistently in `pyproject.toml` and
  `LICENSE`; changing the license is a product decision, not packaging cleanup.
- `issue init --agents` will create `AGENTS.md` as the canonical shared agent
  instructions and a tiny `CLAUDE.md` that imports it. Codex discovers the
  first; Claude Code officially reads the second and does not read AGENTS.md
  directly. One copy of the workflow avoids drift.
- Publishing stays tag-triggered in GitHub Actions and uses PyPI Trusted
  Publishing. No repository secret or long-lived package token belongs here.
- The public project and Python distribution are named CLIIT / `cliit`. The
  descriptive internal module stays `cli_issue_tracker`, and `issue` remains
  the primary command; `cliit` is shipped as an equivalent executable alias.
  This makes the requested brand installable without breaking the concise
  command already documented throughout the interface.
- `uv_build` normally derives the module directory from the distribution name,
  so `module-name = "cli_issue_tracker"` is explicit. The public rename does
  not force an internal import rename or break existing Python references.

## Discoveries

- The repository is still private, so the Git URL shown in README cannot be
  installed by a stranger yet. The final public/publish actions need account
  configuration and remain outside a local code change.
- The current `--agents` implementation creates only AGENTS.md and claims
  Claude reads it. Claude Code's current official documentation says the
  opposite: use a CLAUDE.md import when AGENTS.md is the shared source.
- The baseline is green: all 22 standalone test scripts pass before changes.
- No credential-shaped strings, private keys, dangerous credential files, or
  binary/archive artifacts were found in the working tree or git history. The
  email addresses found are the maintainer contacts in package/community files
  and synthetic test fixtures, not hidden account data.
- PyPI's JSON endpoint returns 404 for `cliit`, so the requested name
  appears available, but only the pending trusted publisher reserves it.
- The wheel and source distribution pass `twine check`; the wheel installed
  in a fresh Python 3.13 environment outside this checkout, created a tracker,
  configured both agent files, and returned valid JSON.
- `pip-audit` reports no known vulnerabilities in the locked runtime
  dependencies. `zizmor` reports no findings in either GitHub Actions
  workflow after actions were commit-pinned, permissions narrowed, checkout
  credentials disabled, and the tag shell interpolation removed.
- Final verification is green: all 22 test scripts, `issue check`, locked
  dependency resolution, README anchors, both distribution checks, and the
  source archive contents.
- The renamed `cliit-0.1.0` wheel installs both console entry points and each
  reports version 0.1.0. `uv_build` initially rejected the distribution/module
  name mismatch as designed; declaring `module-name = "cli_issue_tracker"`
  made that relationship explicit and the clean rebuild passed.
- The first public CI run passed Linux, Windows, the wheel smoke test, the real
  tracker, and the no-git job, but all four macOS jobs exposed a path-identity
  test bug: tempfile reports `/var/...`, while `getcwd()` resolves the same
  directory as `/private/var/...`. The assertion now uses `os.path.samefile`,
  which measures the upward-walk contract rather than an alias spelling.
