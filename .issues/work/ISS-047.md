# ISS-047 Work Plan

## Goal

No CI: every POSIX path in this tool has never run

## Plan

- [x] Settle the version matrix against what the package actually claims
- [x] Write `.github/workflows/ci.yml`: the OS x Python matrix
- [x] Add the wheel job, and prove its command sequence locally first
- [x] Add the no-git job
- [x] Run the suite locally with git off PATH, since that job cannot be
      dry-run on this machine any other way
- [x] Fix what that run found
- [x] README: the CI paragraph, beside the section on the checks themselves

## Decisions

- **requires-python went from >=3.13 to >=3.11, measured rather than
  assumed.** The issue asks for a 3.11-3.13 matrix and `uv sync` refuses
  every job below the floor in pyproject, so the matrix as specified would
  have been six red jobs for a metadata reason. Rather than narrow the matrix
  to 3.13, the whole suite was run on a real 3.11 interpreter: all 21 files
  pass. So the floor was the unverified claim, not the matrix. Classifiers
  for 3.11 and 3.12 went with it.
- **The no-git job runs the whole suite, not just `test_degraded.py`.**
  Running only the file that already knows about the case would not catch a
  new `run_git` caller added under some other command's test.
- **The two failures it found were fixed here rather than filed.** The
  acceptance says whatever fails is filed rather than fixed, and that is the
  right rule for a finding about the tool. These were not that: both were the
  tests' own git fixtures, and a job that is red by construction is a broken
  job rather than a finding.

## Discoveries

- Running the suite with git off PATH failed `test_close.py` and
  `test_log.py`, both with `FileNotFoundError` from `subprocess.run`, and
  neither inside the tool. `storage.run_git` catches exactly that and answers
  128 with "git is not installed"; the two test files each shelled out to git
  directly and so never got that answer.
  - `test_close.head_sha()` had the right intent already documented - "empty
    outside a repo, which is exactly the case require_commits skips" - and
    had reimplemented `run_git` without the catch. It now calls `run_git`.
  - `test_log.py` builds a real repo with real commits as its fixture, so
    with no git there is nothing there to be wrong about. It skips, and says
    so. `test_degraded.py` already holds the no-git contract for `log_issue`.
- The wheel job's smoke sequence was run locally against a real built wheel
  in a clean venv before being written down: `--version`, `init`, `create`,
  `list --json` and `next` all exit 0 outside any source tree. `create` takes
  positional title and description, not the `--body` flag a first draft of
  the job assumed.
