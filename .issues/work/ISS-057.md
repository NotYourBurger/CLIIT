## Decisions

- The channel is email, not GitHub's private advisory form. The form is the
  better door - structured, no inbox to lose it in - but it does not exist on
  a private repository, and the address is already public in
  `pyproject.toml`. One channel that works today beats two where the
  preferred one 404s. Added to ISS-054's scope so it gets turned on at the
  same moment the repository does.
- SECURITY.md answers "what counts as one here" from the real boundary rather
  than a template's. This tool has no server and no privileges; the boundary
  is a `.issues/` directory arriving over `git pull`. So the in-scope list is
  the four rules the code already keeps - `clean_set`, `require_id`,
  `run_git`, `write_atomic` - each named with its test, and the out-of-scope
  list is the documented Non-goals, so a reporter can tell a flaw from the
  design without reading the source.
- No "supported versions" table. There is no release, so a table of versions
  would be one row saying `main`, which is a sentence.
- One issue template, not three. ISS-052 made GitHub Issues the door for
  bugs *and* questions; blank issues stay enabled so a question needs no
  form, and only the bug report gets fields, because only the bug report has
  an answer the maintainer always needs and never gets.
