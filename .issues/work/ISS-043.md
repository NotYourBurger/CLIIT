# ISS-043 Work Plan

## Goal

read_plan and git both raise where their docstrings promise they cannot

## Plan

- [x] tests/test_degraded.py: a plan with a planted bad byte, red
- [x] read_plan decodes with errors= and names the path on stderr
- [x] test: every git-reading command with git off PATH, red
- [x] one git runner low enough for all six callers; route them through it

## Decisions

- The seam is the command functions through `helpers.run()`, the same seam
  every other check here uses. Not `subprocess.run` - mocking the thing under
  test is how you get a green suite and a crashing tool.
- Both halves are one file, `tests/test_degraded.py`: the theme is not "plans"
  or "git", it is a documented no-raise contract that raises.

## Discoveries

- The runner had to land in `storage.py`, not stay in `plan.py`: one of the six
  callers is `fields.current_user`, which is under `plan.py` in the import
  order. The rule CLAUDE.md already states about `issues.py` answers it - a
  thing two layers both want belongs in the lower one.
- `plan.git` keeps its stdout-or-None interface rather than being replaced.
  Two of the six callers need the return code and one needs stderr, so the
  shared piece is the call, not the interpretation; `run_git` returns a
  CompletedProcess and `plan.git` stays the narrow reading of it.
- The stand-in for a missing binary answers 128, which is what git answers for
  "cannot do this here". `require_commits` tests exactly that code first, so
  the missing binary takes the skip that was already written for no repo.
- The .py sources are CRLF in the working tree and LF in the index
  (`core.autocrlf=true`, and `.gitattributes` pins only `.issues/`), so an
  editing pass has to normalise on read or match nothing.
