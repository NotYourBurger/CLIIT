## Decisions

- MIT, author's call. Author is "Tahmid Khan Alim",
  tahmidkhanofficial@gmail.com - the address in pyproject was a different
  personal one and the author replaced it deliberately, knowing a publish
  makes it public.
- The seam is the command line, not a `version()` function: the acceptance
  criterion is literally `uv run issue --version`, and a helper returning a
  string would pass while the flag was unwired. typer ships `CliRunner`, so
  this costs no dependency.
- The expected version is read from pyproject.toml with `tomllib`, not from
  `importlib.metadata` - asking the code for the answer it produced would
  pass by construction. Two sources, and the check is that they agree.

## Discoveries

- `license = "MIT"` plus `license-files = ["LICENSE"]` is the PEP 639 spelling
  and uv_build honours it: the wheel carries `License-Expression: MIT` and
  `dist-info/licenses/LICENSE`, so the license travels with an install rather
  than only living in the repo.
- The wheel-installs criterion is verified by hand and not kept in the suite:
  a build plus a fresh venv per run is ten seconds every test run to catch a
  packaging change nobody makes weekly. The cheap half of it - that the
  installed distribution's version and pyproject's agree - is asserted, and
  that is the assertion that actually catches a drifting number.
