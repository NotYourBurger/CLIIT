Release 0.1.1 with a fixed hero, install line and terminal demo

- [x] Write `docs/demo.sh` - the exact scripted session, runnable and deterministic

## Decisions

- One issue, not three: the hero is what the release carries to PyPI, so it has
  to land before the tag or 0.1.2 exists only to fix copy.
- Demo recorder: no vhs/asciinema/ffmpeg on this machine and Windows has no pty,
  but WSL Ubuntu has python3 + uv. Record with asciinema in WSL, render with a
  prebuilt `agg` binary - both user-local, no apt, no sudo.
- The `.cast` is committed next to the GIF: it is text, it diffs, and it is the
  thing that makes the GIF reproducible. Same reason `.issues/` is Markdown.

## Discoveries

- The README image had to be an absolute raw.githubusercontent URL. PyPI
  renders the README with no repository context, so `docs/demo.gif` would have
  been a broken image on exactly the page this release exists to fix.
- `git` opens a pager on a tty and clears the screen when it leaves, which ate
  the closing diff out of the first recording. `GIT_PAGER=cat` in the script.
- Recorded from WSL: Windows has no pty, so asciinema cannot record here. `uv
  tool install asciinema` plus the prebuilt `agg` binary, both user-local.
- 26.6s, 243K. `uvx twine check` passes on both distributions.

- The release is tag-driven and the `pypi` environment needs maintainer
  approval (`docs/RELEASING.md`), so the last two checkpoints are not mine to
  close - I prepare the commit, the maintainer pushes `v0.1.1`.
