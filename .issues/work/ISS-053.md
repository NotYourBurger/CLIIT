## Decisions

- The enumeration is a subset assertion, not an equality one. The README
  promises the shapes are stable in what they contain and not in what they
  omit, so a test that failed on an added key would contradict the promise it
  guards.
- "Every documented key always present" is not the same as "every key". An
  issue's optional file fields - `priority`, `labels`, `assignee`,
  `updated_at`, `resolution`, `plan` - are absent-means-absent by a rule the
  README states separately, so the enumeration splits: eight keys always on
  every issue object, and the optional ones asserted against the one fixture
  that carries each. `brief` is the opposite case and its every key is
  unconditional, which is what the empty-repo pass is for.

## Discoveries

- The first draft failed its own acceptance criterion. Two assertions - an
  equality against ALWAYS for the bare fixture, and a closed vocabulary over
  every emitted key - failed when a key was *added*, which is the one thing
  the README says may happen. Both were deleted: "absent means absent" is
  expressible as `not SOMETIMES & set(issue)`, which says the same thing and
  survives a new key. Every nested equality went the same way, so the whole
  file is subsets now. A test that fails on what its own promise allows is a
  test somebody deletes rather than reads.
- A mistyped status word is read as an id, not as a bad status: `set` pops
  the trailing word only when it is in STATUSES, so `issue set ISS-003 opne`
  is "unknown id opne" and the write to ISS-003 still lands. That made the
  first refused-write case assert the wrong thing. `--priority` is the real
  refusal path - `require_priority` exits before anything touches disk - so
  that is what the exit-code check uses. The id-shaped error message is
  already deliberate (`set_fields` says so in a comment); noted, not changed.
- Mutation-checked, one key at a time: removing `blocks`, `labels`,
  `assignee`, `priority`, `resolution` or `brief`'s `warnings` each fails
  this file, and adding a key passes it.
