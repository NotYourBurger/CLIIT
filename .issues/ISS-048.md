# requires-python >= 3.13 is not backed by anything

pyproject pins `requires-python = ">=3.13"`. Nothing in the source needs it.
The newest syntax anywhere is a walrus in `issues.py`, which is 3.8, and two
independent reads of all four thousand-odd lines found no 3.13-only feature.

There is evidence it already runs on less. `src/cli_issue_tracker/__pycache__`
holds `cpython-312` bytecode next to the 313 files, and the interpreter on
PATH on the dev machine is 3.12.10 - so this code has been executed under a
version its own manifest forbids installing on.

The cost is the install base. 3.13 is new enough to exclude most distro and
CI default interpreters, for a CLI with three dependencies.

## Scope

Set the floor to whatever CI proves, not to what `.python-version` happens to
say. `.python-version` is the dev machine's choice and should stay as it is.

## Acceptance

- requires-python matches the oldest version the suite passes on in CI
- if 3.13 does turn out to be required, a comment in pyproject names the
  feature that requires it
