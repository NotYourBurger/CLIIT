# Nothing says which shapes a stranger may depend on

Several things in this tool are already stable by accident: designed
carefully, relied on daily, and never declared.

- the `.issues/*.md` frontmatter format
- the `--json` shapes on list, next, brief, search, check and event
- the exit-code contract: 0 for a filter matching nothing, 1 for a lookup
  finding nothing
- `ISSUES_DIR`, `ISSUE_PREFIX`, `ISSUE_USER`

The moment an outsider has a `.issues/` directory of their own, changing any
of these stops being a change and becomes a migration. There is no version to
hang a promise on either, which ISS-046 covers.

The cheap answer is a written policy, not a mechanism. Unknown frontmatter
keys are already preserved on rewrite, which is real forward compatibility,
so a format version key would be a commitment bought before it is needed.

## Scope

A short STABILITY section: what semver covers once there is a version, what
is explicitly unstable before 1.0, and which of the four groups above is
which.

A frozen golden corpus for the file format belongs here as a decision rather
than as work. It is the mechanism this policy needs if the answer turns out
to be "stable", and it is wasted if the answer is "not yet".

## Acceptance

- one written answer to whether another tool may read and write `.issues/*.md`
- the json shapes and the exit codes are each named as covered or not covered
- no format version key is added unless the policy says the format is stable
