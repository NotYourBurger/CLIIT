# The README is a reference, and a newcomer needs a path

936 lines, and the first heading a stranger meets after the description is
`## Non-goals`. The document is a good specification and a poor introduction:
it answers every question except the two a new arrival actually has, which are
how do I install this and what do I type first.

One half of the install answer is wrong in a way prose cannot fix - `uv sync`
needs a clone and a uv already installed - and that half waits on ISS-054. The
rest does not. The ordering, the headings, and the fact that nothing on the
page says what this is in the words somebody would search for are all fixable
today, and nothing that is written now has to be unwritten when the release
lands.

Searchability is not decoration here. "Markdown issue tracker", "git-based
issue tracker", "issue tracker for AI coding agents" are what somebody types
when they have the problem this solves, and not one of them appears in a
heading. Headings are the index that a search engine and a skimming human both
read, and this file's headings are named for their role in the document rather
than for the thing being looked for.

## Scope

- a top section a stranger can act on: what it is, install, the first few
  commands, in that order
- headings named for what is being searched for, not for the section's job
- the reference material kept, moved below the getting-started path
- Non-goals, Stability and File format unchanged in wording: they are
  promises, not copy

## Acceptance

- somebody who has never seen this repo can install it and create their first
  issue from the top of the README alone
- no install instruction that does not work today is written as though it does
- the four stability promises read exactly as they read now
