# The README says what the commands are, not who it is for

Eight hundred and fifteen lines, and the first sixty are a verb list. A
stranger deciding in thirty seconds whether this is for them gets no answer:
no statement of who it is aimed at, no worked example of the loop it is
actually good at, and no non-goals.

The non-goals matter more than usual here, because the design has real edges
that read as missing features when nobody names them: one repo per tracker,
no server, no web UI, no id allocation across forks, git required for
history. Saying them out loud turns each one from a disappointment into a
deliberate scope.

## Scope

A header above the existing reference: what it is in two sentences, who it is
for, a thirty-second worked example, and an honest non-goals list. The verb
list stays exactly as it is underneath - it is a good reference and is not
the thing that is missing.

## Acceptance

- a reader who has never seen this repo can decide in under a minute
- the non-goals are stated rather than implied
