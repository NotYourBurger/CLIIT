# A first contributor has to read 936 lines to learn the loop

The conventions here are real and almost entirely unwritten outside CLAUDE.md,
which is addressed to an agent rather than to a person: work starts with
`issue start ISS-NNN`, the plan is ticked as the work happens rather than at
the end, commits are prefixed with the issue id, new behaviour lands with its
own `tests/test_<thing>.py` holding a `demo()` that asserts and prints ok, and
there is deliberately no linter and no test framework.

Every one of those is something a stranger gets wrong on a first pull request,
and each one wrong is a review round trip that discourages the second pull
request.

CLAUDE.md is not the place to send them. It is the agent's file, it carries
repo internals a contributor does not need, and ISS-045 already decided that
two files carrying the same prose is one file that goes stale. So CONTRIBUTING
says what CLAUDE.md does not, and links rather than repeats.

## Scope

CONTRIBUTING.md: setup, the work loop end to end as commands, the
commit-message convention, what a test looks like here, and the answer ISS-052
gives about where a bug is filed and whether a pull request may touch
`.issues/`.

## Acceptance

- the loop is shown as commands somebody can run, not described in prose
- the no-linter, no-framework decision is said out loud so nobody adds one
  helpfully
- nothing is copied out of CLAUDE.md; it is linked
