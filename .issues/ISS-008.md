# Machine readable output for list and view

`issue list` prints a column-padded table. That is right for a human and useless
for anything else - piping it into a script means re-parsing the padding that
`list_issues` just carefully added.

Add `--json` to `list` and `view`, emitting the issue dicts `parse_issue` already
returns.

## Why

The data model is already a `dict` of exactly the right shape. The only thing
between it and `json.dumps` is the formatting layer. This is a few lines, not a
feature.

It also makes the tool composable with things that are not this tool:

```bash
issue list --json | jq -r '.[] | select(.status=="open") | .id'
```

## Design note

Keep `--json` a flag on the existing commands rather than a separate `export`
command. One code path collects the issues; the flag only chooses the renderer.
The collect-then-render split in `list_issues` is already sitting there ready
for it.

`view --json` should include `body` verbatim. That is the field an external
reader actually wants and the one the table cannot carry.
