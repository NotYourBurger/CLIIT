# Short-prefix id resolution

Blocked by ISS-059, and the cost of it: `ISS-0m4k3f9a` is materially worse to
type than `ISS-42`. Agents copy-paste ids and do not care; humans do.

Git answered this with short SHAs and the same answer fits. When
`storage.read_issue` finds no exact match, resolve a unique id prefix -
`issue view 0m4k` - and refuse an ambiguous one by naming the candidates.

Deliberately a lookup and not a shape change: `require_id` stays the
door-level guard it is, and nothing below `read_issue` learns about prefixes.

Filed separately because it is a usability patch on the migration rather than
part of it. If ISS-059 ships without it, this is the regression.

## Acceptance

- a unique prefix resolves on every verb that takes an id
- an ambiguous prefix exits 1 and names the candidates
- an exact id always wins over a prefix match
- a prefix matching nothing is the existing "not found", exit 1
