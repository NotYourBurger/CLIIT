# Record when an issue last changed

Issues carry `created_at` and nothing else. `issue set ISS-001 closed` rewrites
the file and leaves no trace of when.

## What breaks because of it

- `issue list` cannot answer "what moved recently" or "what has been open for
  three weeks", which is the actual question when you come back to a project
- an issue closed today and one closed in March look identical
- the `in-progress` group is the one that most needs a staleness signal, and it
  has none

## Scope

Add `updated_at` to the frontmatter, stamped in `write_issue` - one place,
because every write already goes through it.

## Careful

`parse_issue` requires `id`, `status`, `created_at`, `title` and returns `None`
for a file missing any of them. Do **not** add `updated_at` to that required
list: the four issues already on disk do not have it, and they would all
silently disappear from `issue list`. Treat a missing `updated_at` as "unknown"
and let the next write fill it in.

## Open question

columns is already wide. Possibly `view` only.
